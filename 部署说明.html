零基础部署说明

目标只有一个：你不需要学 Git、不需要租服务器、不需要碰命令行。全程只在 GitHub 与 Supabase 的网页界面里点击、复制、粘贴。

00

开始前准备

  1. 注册一个 GitHub 账号。
  2. 注册一个 Supabase 账号。
  3. 把下载到电脑的 V3 ZIP 解压。
  4. 不要把 RAW 原片放进 GitHub。这个项目只把网页代码放 GitHub；照片以后从你的管理后台上传到 Supabase。
你整个过程中不会用到终端、Node、npm、Git 命令。
01

在 Supabase 创建项目

  1. 打开 Supabase Dashboard 并登录。
  2. 点击 New project。
  3. Project name 可以填：photo-archive。
  4. Database Password 让 Supabase 自动生成一个强密码，保存到你的密码管理器。这个密码以后基本不会用到。
  5. Region 选择离你较近的地区。
  6. 点击 Create new project。
  7. 等待项目首页出现。
02

创建照片存储空间

  1. 在 Supabase 左侧点击 Storage。
  2. 点击 New Bucket。
  3. Name 必须填写：photos。
  4. 把 Public bucket 打开。
  5. 如果界面允许设置文件大小，建议填 20 MB；Allowed MIME type 可填 image/jpeg。
  6. 点击 Create Bucket。
网页会把你选中的 JPEG / PNG / WebP 先在浏览器里生成优化后的 JPEG，再上传到这个 bucket。原始照片不会被 GitHub 保存。
03

初始化数据库与安全规则

你不需要理解下面的 SQL。只做一次“全选复制 → 粘贴 → Run”。

  1. 在 Supabase 左侧点击 SQL Editor。
  2. 点击 New query。
  3. 点击下面的“复制整段 SQL”。
  4. 回到 Supabase 的编辑框，粘贴。
  5. 点击右下角或顶部的 Run。
  6. 看到 Success / No rows returned 一类成功提示即可。

-- V3 摄影档案：Supabase 数据库初始化
-- 使用方式：Supabase Dashboard → SQL Editor → New query → 全选粘贴 → Run
-- 这段脚本不会创建登录用户，也不会创建 Storage bucket；这两项按部署说明在网页界面点击完成。

create table if not exists public.photos (
  id uuid primary key default gen_random_uuid(),
  owner_id uuid not null default auth.uid() references auth.users(id) on delete cascade,
  title text not null default '未命名',
  project text not null default '未分类',
  note text not null default '',
  storage_path text not null unique,
  original_name text,
  mime_type text default 'image/jpeg',
  bytes bigint,
  uploaded_at timestamptz not null default now(),
  date_taken timestamptz,
  make text,
  model text,
  camera text,
  lens text,
  focal_length numeric,
  focal_length_35mm numeric,
  aperture numeric,
  exposure_time numeric,
  iso integer,
  exposure_compensation numeric,
  width integer,
  height integer,
  orientation integer,
  is_featured boolean not null default false,
  sort_order integer not null default 0
);

create index if not exists photos_project_idx on public.photos(project);
create index if not exists photos_date_taken_idx on public.photos(date_taken desc nulls last);
create index if not exists photos_uploaded_at_idx on public.photos(uploaded_at desc);

alter table public.photos enable row level security;

-- 明确限制 Data API 权限：未登录访客只能读取，登录用户才有增删改。
revoke all on table public.photos from anon, authenticated;
grant select on table public.photos to anon;
grant select, insert, update, delete on table public.photos to authenticated;

-- 重复运行本脚本也不会因为旧策略而报错。
drop policy if exists "public can read photos" on public.photos;
drop policy if exists "authenticated can insert own photos" on public.photos;
drop policy if exists "owner can update own photos" on public.photos;
drop policy if exists "owner can delete own photos" on public.photos;

create policy "public can read photos"
on public.photos for select
to anon, authenticated
using (true);

create policy "authenticated can insert own photos"
on public.photos for insert
to authenticated
with check (owner_id = (select auth.uid()));

create policy "owner can update own photos"
on public.photos for update
to authenticated
using (owner_id = (select auth.uid()))
with check (owner_id = (select auth.uid()));

create policy "owner can delete own photos"
on public.photos for delete
to authenticated
using (owner_id = (select auth.uid()));

-- Storage bucket 必须在 Dashboard 中手动创建，名称严格为 photos，并设置为 Public。
-- 以下策略只负责“谁可以上传/删除”，公开 bucket 的图片读取由 Storage 的 Public access 负责。
drop policy if exists "authenticated can view photo objects" on storage.objects;
drop policy if exists "authenticated can upload photo objects" on storage.objects;
drop policy if exists "owner can update photo objects" on storage.objects;
drop policy if exists "owner can delete photo objects" on storage.objects;

create policy "authenticated can view photo objects"
on storage.objects for select
to authenticated
using (bucket_id = 'photos');

create policy "authenticated can upload photo objects"
on storage.objects for insert
to authenticated
with check (
  bucket_id = 'photos'
  and (storage.foldername(name))[1] = (select auth.uid()::text)
);

create policy "owner can update photo objects"
on storage.objects for update
to authenticated
using (
  bucket_id = 'photos'
  and owner_id = (select auth.uid()::text)
)
with check (
  bucket_id = 'photos'
  and owner_id = (select auth.uid()::text)
);

create policy "owner can delete photo objects"
on storage.objects for delete
to authenticated
using (
  bucket_id = 'photos'
  and owner_id = (select auth.uid()::text)
);
04

取得 Supabase 的两项连接信息

  1. 回到 Supabase 项目首页。
  2. 点击页面上的 Connect；如果找不到，也可以进入 Settings → API Keys。
  3. 找到并复制 Project URL，它类似：https://xxxx.supabase.co。
  4. 找到并复制 Publishable key，它通常以 sb_publishable_ 开头。
不要复制 Secret key。
V3 只使用 Publishable key。它是 Supabase 专门设计给浏览器公开使用的低权限密钥，真正权限由数据库 RLS 和你的登录账号决定。
05

在 GitHub 创建网站仓库

  1. 打开 GitHub 新建仓库页面。
  2. Repository name 最省事的写法是：你的GitHub用户名.github.io。例如用户名是 chenphoto，就填 chenphoto.github.io。
  3. Visibility 选择 Public。
  4. 不用添加 README、.gitignore 或 License。
  5. 点击 Create repository。
06

把 V3 文件上传到 GitHub

  1. 打开你刚创建的仓库。
  2. 点击 Add file → Upload files；如果仓库完全空白，也可以点页面里的 uploading an existing file。
  3. 在电脑里打开解压后的 lavoie_portfolio_v3 文件夹。
  4. 拖入这个文件夹里面的全部内容，包括 index.html、assets、setup 等。不要把最外层文件夹本身再套一层。
  5. 页面下方 Commit message 可以写：上传摄影档案 V3。
  6. 选择直接提交到 main，点击 Commit changes。
GitHub 网页支持直接拖放文件或文件夹。这个 V3 项目文件数量很少，不需要 Git 命令。
07

在 GitHub 网页填写连接信息

  1. 在仓库文件列表依次点击 assets → js → config.js。
  2. 点击右上角的铅笔图标 Edit this file。
  3. 把 PASTE_SUPABASE_PROJECT_URL_HERE 替换为刚才复制的 Project URL。
  4. 把 PASTE_SUPABASE_PUBLISHABLE_KEY_HERE 替换为 Publishable key。
  5. 把 siteName: '你的名字' 中的“你的名字”改成你希望网站显示的名字。
  6. 不要改变左右引号、逗号和其他内容。
  7. 点击 Commit changes…，再确认一次 Commit changes。

正确示意：

window.PHOTO_ARCHIVE_CONFIG = {
  supabaseUrl: 'https://xxxx.supabase.co',
  supabaseKey: 'sb_publishable_xxxxxxxxx',
  siteName: '你的名字',
  siteSubtitle: '摄影档案',
  storageBucket: 'photos',
  maxUploadEdge: 2560,
  jpegQuality: 0.88
};
08

打开 GitHub Pages

  1. 在仓库顶部点击 Settings。
  2. 左侧找到 Pages。
  3. 在 Build and deployment 下，把 Source 选择为 Deploy from a branch。
  4. Branch 选择 main，文件夹选择 /(root)。
  5. 点击 Save。
  6. 稍后刷新这个 Pages 页面，看到 Visit site 后点击。

如果你按前面建议把仓库命名为 用户名.github.io，网站地址通常就是：

https://你的GitHub用户名.github.io/
09

创建你唯一的后台账号

  1. 回到 Supabase。
  2. 左侧点击 Authentication → Users。
  3. 点击 Add user。
  4. 如果菜单里有 Create new user，选择它。
  5. 填写你自己的邮箱与一个强密码。
  6. 把 Auto Confirm User 勾上。
  7. 点击 Create user。

然后关闭任何人自行注册

  1. 进入 Supabase 的 Authentication 设置 / General Configuration。
  2. 找到 Allow new users to sign up。
  3. 把它关闭。
这样项目中只有你创建的这个账号能登录。即使别人知道你的 Publishable key，也不能获得后台增删改权限。
10

第一次登录和上传测试

  1. 打开：https://你的GitHub用户名.github.io/admin.html。
  2. 输入刚才创建的 Supabase 邮箱和密码。
  3. 登录后，在“系列名称”填：测试 / 2026。
  4. 先选择 1 张相机 JPEG 测试。
  5. 点击 上传并读取 EXIF。
  6. 上传完成后打开网站顶部的 档案 与 数据。

如果照片本身包含标准 EXIF，你应该能看到设备、镜头、焦段、光圈、快门、ISO 等数据。

11

以后你每天怎么用

部署完成后，你基本不再碰 GitHub 与 Supabase 后台。

  1. 打开 /admin.html。
  2. 如果浏览器还保留登录状态，会直接进入后台。
  3. 填写系列名称。
  4. 拖入照片。
  5. 点击上传。
  6. 首页、档案、详情和统计自动使用新数据。
GitHub 只在以后要改网站设计或功能时才需要打开。
12

快速自检

最常见的 4 个问题

1. “网站还没有连接 Supabase”
检查 GitHub 里的 assets/js/config.js 是否已经填入 Project URL 与 Publishable key，并 Commit。

2. 上传时报 RLS / 403
重新执行第 03 步 SQL；再确认 Storage bucket 名字严格是 photos。

3. 照片能上传但没有 EXIF
先用相机原始导出的 JPEG 测试。经过微信、社交平台、某些修图 App 导出的文件经常已经删除 EXIF。

4. 页面 404
检查 GitHub Pages 的 Branch 是否为 main、文件夹是否为 /(root)，并确认 index.html 在仓库最外层。

13

你需要知道的隐私边界

  • 这个版本的前台作品是公开访问设计。
  • 后台只有登录用户才能增删改。
  • 上传前 EXIF 在浏览器本地读取；数据库不保存 GPS 字段。
  • 上传到 Supabase 的是重新生成的网页 JPEG，因此不会把原文件的 GPS/EXIF 整包带到公网。
  • RAW 原片请继续保存在你的电脑、移动硬盘或 NAS，不要把 GitHub/Supabase 当唯一备份。

V3 架构：GitHub Pages + Supabase Database / Storage / Auth。说明按 2026-09 的官方产品界面与文档编写；如果未来按钮名称小幅变化，逻辑仍然是相同的。
